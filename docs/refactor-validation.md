# 独立后端重构与验收记录

日期：2026-10-15。代码已实现独立后端、HTTP CLI 和浏览器前端；Linux 模拟验收通过。真实游戏登录、实际 TUN 出口和服务器业务确认尚未验收。

后续增加的多出口分组及独立执行进程，见[多出口分组验收记录](egress-validation.md)；使用方法见[分组操作说明](egress-groups.md)。

## 已实现的边界

- `src/service/application.py` 组合账号、会话、任务、执行、事件和存储服务；协议及脚本不依赖 HTTP 或 CLI。
- `src/interfaces/http.py` 提供 `/api/v1`、Bearer/Cookie 认证、SSE 和网页静态文件；`src/interfaces/cli.py` 通过 HTTP 执行业务操作。
- `src/service/runtime.py` 管理真实登录账号互斥、初始化、在线容量和连接归属；`tasks.py` 管理批处理、取消及最终清理。
- SQLite/SQLAlchemy/Alembic 保存账号与脱敏运行记录，重启将未完成任务标记中断且不重放。数据目录使用进程独占锁。
- `frontend` 使用 Vue、TypeScript、Vite；API 类型由 `docs/openapi.json` 生成。
- 新网络链路忽略应用及环境代理，由外部系统 TUN 决定路由。旧配置迁移仅转换内容，保留原文件。

100 是同时在线容量。101 个目标账号可以在 `bounded` 模式下分批完成；`all_online` 需要预留全部容量，101 个账号会在登录前返回 `capacity_exceeded`。

## 追加验证：2000 个账号的界面响应

2026-10-15 使用同机 Edge 155.0.4283.45、同一组 2000 个模拟账号和模拟离线会话，对比生产构建。所有业务 API 均被拦截，未接触用户账号、数据库或游戏服务。延迟测量从点击开始，等待 Vue 更新和两次浏览器绘制调度；下表为中位数。

| 操作 | 修复前 | 修复后 |
|---|---:|---:|
| 单个账号勾选/取消（6 次） | 2878 ms | 30.2 ms |
| 全选/清空（4 次） | 5732.9 ms | 31.35 ms |
| 页面实际渲染账号行数 | 2000 | 50 |

瓶颈是全量账号行重绘，以及每行多次线性查找会话；账号较多时，单次重绘累计执行数百万次查找。已增加每页 50 行的分页，用 Map/Set 查找状态和选择，缓存导入报告文本，并将刷新时的已选账号核对改为线性处理。账号、会话和编排页保留跨页选择，全选仍覆盖全部账号。

最新 18 项前端测试、类型检查、OpenAPI 类型一致性和生产构建均通过。新增回归覆盖 2000 账号的渲染行数、跨页选择、全选、账号删除后翻页修正及完整预检账号集合；修复后勾选期间没有 API 请求，桌面与手机页面无运行错误及页面横向溢出。

测量脚本：`frontend/tests/account_performance.py`。原始结果、截图和测试日志保存在已忽略的 `frontend/test-results/account-performance-*` 与 `account-selection-*` 中。数据是模拟测量，真实账号上线时的后台负载仍会影响实际响应。
